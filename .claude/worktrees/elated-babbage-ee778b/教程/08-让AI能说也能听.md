# 第 8 章：让 AI 能说也能听

> 上一章 AI 已经会"打字"了。这章我们让它开口说话，同时让用户也能用语音输入——做完这章，你可以跟 AI 对话，完全不需要打字。

---

## 8.1 让 AI 说话：TTS 的基本思路

TTS（Text-to-Speech，文字转语音）的流程很简单：AI 生成了一段文字 → TTS 引擎把文字合成成音频文件 → 前端播放这个音频。

难点在于：**什么时候合成**？

如果等 AI 把所有文字都生成完再合成，用户要先等 AI 生成（几秒），再等合成（几秒），体验很差。

更好的方案是**句子级流水线**：AI 生成完一句话，立刻把这句话送去合成。用户在听第一句时，第二句已经在合成了，第三句还在生成。三件事同时进行，延迟大幅降低。

这个设计是整个 TTS 系统的核心，其他都是实现细节。

---

## 8.2 选 Edge-TTS

我们用 **Edge-TTS**——微软 Edge 浏览器内置的 TTS 引擎，有人把接口逆向出来做成了 Python 包，免费使用，支持大量中文声音，质量不错。

```bash
pip install edge-tts
```

装好之后可以在命令行测试一下：

```bash
edge-tts --text "你好，我是AI助手" --voice zh-CN-XiaoxiaoNeural --write-media test.mp3
```

会生成一个 `test.mp3`，播放听听效果。常用的中文声音有：`zh-CN-XiaoxiaoNeural`（女，温柔）、`zh-CN-YunxiNeural`（男，温暖）、`zh-CN-XiaoYiNeural`（女，活泼）。

> **试一下**：多试几个声音，找一个你喜欢的，把声音名字记下来，之后放进 `.env` 配置。

## 8.3 后端：tts.py 和 splitter.py

需要写两个新文件。

**`backend/tts.py`**：对外只暴露一个函数 `synthesize(text)`，接受一段文字，调用 Edge-TTS 合成，把音频文件保存到临时目录，返回一个 `/audio/xxx.mp3` 格式的 URL。文件名用 uuid 保证唯一，不会冲突。

声音的配置（用哪个声音、语速快慢）从环境变量读取，这样不用改代码就能切换。

**`backend/splitter.py`**：句子切割器。这个类有一个 `feed(token)` 方法——你把 LLM 生成的每个 Token 喂给它，它维护一个内部缓冲区，每次遇到句号、感叹号、问号这类标点，就把之前积累的内容作为一个完整句子返回。还有一个 `flush()` 方法，在 LLM 生成完毕后调用，处理最后没有标点结尾的剩余文字。

> **你可能会问**：为什么不直接在合成之前把完整文字按句子切割？
>
> 因为我们是流式的——文字是一个 Token 一个 Token 地来的，不知道完整文字是什么。Splitter 的作用就是在流式场景下"实时识别句子边界"，检测到句子结束就立刻送去合成，而不是等到全部生成完。

## 8.4 后端：main.py 里集成 TTS

在 WebSocket 路由里，原来的逻辑是：每来一个 Token，发给前端显示。

现在加上：每来一个 Token，喂给 splitter。如果 splitter 认为一句话完了，就创建一个异步任务去合成这句话。合成完了，把音频 URL 通过 WebSocket 发给前端。

关键代码结构：

```python
splitter = StreamingSentenceSplitter()

async for token in chat_stream(history):
    # 发文字 Token（打字机效果不变）
    await websocket.send_json({"type": "token", "text": token})
    
    # 检查有没有完整的句子出来
    for sentence in splitter.feed(token):
        # 有句子了，异步去合成，不阻塞文字流
        asyncio.create_task(synthesize_and_send(sentence))

# 处理最后一句
for sentence in splitter.flush():
    asyncio.create_task(synthesize_and_send(sentence))
```

`asyncio.create_task()` 的作用是"创建一个后台任务，不等它完成就继续"——这样 TTS 合成和文字流式输出是并发的。

还需要加一个 `/audio/{audio_id}` 路由，让前端能拿到音频文件：

```python
@app.get("/audio/{audio_id}")
async def get_audio(audio_id: str):
    path = get_audio_path(audio_id)
    if not path.exists():
        raise HTTPException(404, "音频不存在")
    return FileResponse(str(path), media_type="audio/mpeg")
```

## 8.5 前端：音频队列

前端会陆续收到多个 `{"type": "audio", "url": "..."}` 消息，每个对应一句话的音频。

问题是：如果前一句还没播完，下一句就来了，不能直接打断播放，要排队等着。所以用一个**音频队列**：

- 收到 audio 消息，把 URL 加入队列
- 队列里有东西、当前没有在播放，就取出第一个播放
- 播放结束后，检查队列里还有没有，有就继续播

```javascript
const audioQueue = [];
let isPlaying = false;

async function playNextAudio() {
    if (isPlaying || audioQueue.length === 0) return;
    isPlaying = true;
    const url = audioQueue.shift();
    const audio = new Audio(`${API_BASE}${url}`);
    await new Promise(resolve => {
        audio.onended = resolve;
        audio.onerror = resolve;  // 出错也继续播下一个
        audio.play();
    });
    isPlaying = false;
    playNextAudio();  // 递归调用，播下一个
}
```

在 `handleServerMessage` 里加上 audio 类型的处理：

```javascript
case "audio":
    audioQueue.push(data.url);
    playNextAudio();
    break;
```

另外加一个静音按钮。在 `playNextAudio` 里检查静音状态，如果是静音，直接跳过（`audioQueue.shift()` 丢弃），不播放。

## 8.6 语音输入：让用户不用打字

有了 TTS，AI 能说话了。现在加上语音输入，让用户也能说话——对话就完全不需要键盘了。

两种方案各有优劣：

**Web Speech API**：浏览器内置，零成本，Chrome 支持好，但对口音和专业词汇识别质量一般，而且需要 HTTPS 才能用（本地 localhost 例外）。

**Whisper API**：OpenAI 的语音识别，质量极高，支持各种口音和方言，但需要后端转发请求，有少量费用（很便宜）。

入门建议先用 Web Speech API，效果不满意再升级 Whisper。

---

## 8.7 方案一：Web Speech API

只需要改前端，后端完全不用动。

在 HTML 的输入区域加一个麦克风按钮 `<button id="mic-btn">🎤</button>`。

在 JS 里初始化 `SpeechRecognition`：

```javascript
const recognition = new (window.SpeechRecognition || window.webkitSpeechRecognition)();
recognition.lang = "zh-CN";
recognition.interimResults = true;  // 返回中间结果，实时显示在输入框里
```

`interimResults: true` 是关键——开启后，用户说话的过程中，识别出的文字会实时出现在输入框里，体验和真正的语音输入一样流畅。

```javascript
recognition.onresult = (event) => {
    let text = "";
    for (let i = event.resultIndex; i < event.results.length; i++) {
        text += event.results[i][0].transcript;
    }
    messageInput.value = text;  // 实时更新输入框
};

recognition.onend = () => {
    stopRecording();
    if (messageInput.value.trim()) {
        sendMessage();  // 说完自动发送
    }
};
```

点击麦克风按钮时，如果已经在录音就停止，否则开始录音。麦克风按钮的视觉状态（普通 / 录音中）靠 CSS class 切换。

> **试一下**：点麦克风，说"你好"，看看输入框里有没有实时出现文字，说完有没有自动发送。如果 Chrome 弹出麦克风权限请求，允许它。

## 8.8 方案二：Whisper（高精度升级）

如果 Web Speech API 识别效果不理想，可以用 Whisper。

流程变了：不是浏览器直接识别，而是用 `MediaRecorder` 把录音录成一个音频文件，然后 POST 到后端，后端再转发给 Whisper API，把识别结果返回前端。

**后端**：加一个 `/api/transcribe` 接口，接收上传的音频文件，用 httpx 转发到 Whisper API，返回识别出的文字。

```python
@app.post("/api/transcribe")
async def transcribe(audio: UploadFile = File(...)):
    audio_bytes = await audio.read()
    # 转发到 Whisper API
    async with httpx.AsyncClient(timeout=30.0) as client:
        response = await client.post(
            "https://api.openai.com/v1/audio/transcriptions",
            headers={"Authorization": f"Bearer {WHISPER_API_KEY}"},
            files={"file": ("audio.webm", audio_bytes, audio.content_type)},
            data={"model": "whisper-1", "language": "zh"},
        )
    return {"text": response.json().get("text", "")}
```

**前端**：用 `MediaRecorder` 录音，停止时把录音 blob 包成 `FormData`，POST 到 `/api/transcribe`：

```javascript
const blob = new Blob(audioChunks, { type: "audio/webm" });
const formData = new FormData();
formData.append("audio", blob, "recording.webm");
const res = await fetch(`${API_BASE}/api/transcribe`, { method: "POST", body: formData });
const { text } = await res.json();
messageInput.value = text;  // 显示识别结果，用户确认后手动发送
```

注意 Whisper 不自动发送——识别结果显示在输入框，用户看一眼确认没问题再按 Enter 发送，避免误操作。

## 8.9 测试完整流程

做完这章之后的完整体验：

用户点麦克风，说一段话 → 文字出现在输入框 → 发送 → AI 文字逐渐显示（打字机效果）→ 几秒后听到 AI 说话的声音（第一句）→ 声音持续按句子播放 → 完成

> **试一下**：问 AI 一个需要几句话回答的问题，注意观察：第一句语音出来的时间，是不是比"等 AI 全部说完再播"快很多？这就是句子级流水线的效果。

---

## 本章小结

- TTS 句子级流水线：检测到句子结束立刻合成，不等全部文字生成完
- `asyncio.create_task()` 让 TTS 合成和文字流式输出并发进行
- 音频队列保证多句话按顺序播放，不互相打断
- Web Speech API：浏览器内置，改前端就够，`interimResults: true` 实时显示识别中间结果
- Whisper：`MediaRecorder` 录音 → blob → FormData POST → 后端转发 → 识别结果
