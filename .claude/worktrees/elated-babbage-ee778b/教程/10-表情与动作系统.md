# 第 10 章：表情与动作系统

> 上一章 Live2D 模型能动嘴了，但表情一成不变——不管 AI 说什么都是一个样子。这章我们引导 AI 在回复里"夹带"控制指令，让它说开心的话时切成开心表情，说话时配上相应动作。

---

## 10.1 让 AI 自己控制表情

最直接的思路：让 AI 在回复里插入控制标签，后端解析出来，转发给前端。

我们约定一个格式：
- `[emotion:happy]`：切换到开心表情
- `[emotion:sad]`：切换到难过表情
- `[motion:Wave]`：播放挥手动作
- `[motion:Nod]`：播放点头动作

AI 生成的回复可能是这样：

```
[emotion:happy]你好呀！很高兴认识你～[motion:Wave]
```

后端解析之后：
- 发给前端一个 `{"type": "expression", "name": "happy"}` 事件
- 发给前端文字 `你好呀！很高兴认识你～`
- 发给前端一个 `{"type": "motion", "group": "Wave"}` 事件

前端收到事件，立刻调用 Live2D 切换表情、播放动作。

---

## 10.2 更新系统提示词

要 AI 配合使用这些标签，需要在系统提示词里说清楚。更新 `backend/.env` 的 `SYSTEM_PROMPT`：

```
SYSTEM_PROMPT=你是一个友好的AI虚拟助手。在回复时，可以用以下标签控制你的虚拟形象：

表情标签（放在句子开头）：
[emotion:happy] - 开心、高兴
[emotion:sad] - 难过、同情  
[emotion:surprised] - 惊讶
[emotion:thinking] - 思考中

动作标签（放在句子末尾）：
[motion:Wave] - 挥手打招呼
[motion:Nod] - 点头同意
[motion:Shake] - 摇头

标签不会显示给用户，只控制形象。自然使用，不要每句都加。
```

> **你可能会问**：AI 真的会按照系统提示词的格式输出标签吗？
>
> 大多数时候会，但不是 100%。它可能会忘记加标签，也可能格式稍有偏差。所以解析的时候要做好容错——标签格式不对就忽略，当作普通文字处理，不能让它导致崩溃。

## 10.3 后端：parser.py

新建 `backend/parser.py`，处理从 LLM 流式输出中解析标签这件事。

这里有一个棘手的问题：LLM 是流式输出的，标签可能被分割在多个 Token 里。比如 `[emotion:happy]` 可能先来 `[em`，再来 `otion:`，最后来 `happy]`。所以不能直接对每个 Token 做正则匹配，要维护一个缓冲区，等标签完整了再处理。

**`StreamingParser` 类**的工作原理：
1. 维护一个字符串缓冲区
2. 每次 `feed(token)` 把新的 Token 追加进去
3. 扫描缓冲区：如果不含 `[` 就把内容全部输出为文字；如果含 `[`，先输出 `[` 之前的文字，然后等待 `[...]` 结束
4. `[...]` 结束后，用正则判断是哪种标签，返回对应的动作对象
5. `flush()` 方法在 LLM 生成完毕后调用，处理缓冲区里剩余的内容

输出用三种数据类（dataclass）表示：
- `EmotionAction(name="happy")`
- `MotionAction(group="Wave", index=0)`
- 纯文字（字符串）

这样在 WebSocket 路由里，就可以用 `isinstance` 判断每个解析结果的类型，分别处理。

还需要一个 `strip_tags(text)` 函数，用于在存历史记录之前，把标签从 AI 回复里去掉——历史里存干净的文字，不然下次发给 LLM 的上下文里会带着一堆控制标签，影响生成质量。

## 10.4 更新 WebSocket 路由

在 `main.py` 的 WebSocket 路由里，原来是直接把每个 Token 发给前端。现在改成先经过 `StreamingParser.feed()`，再根据结果类型分别处理：

```python
for item in parser.feed(token):
    if isinstance(item, EmotionAction):
        await websocket.send_json({"type": "expression", "name": item.name})
    elif isinstance(item, MotionAction):
        await websocket.send_json({"type": "motion", "group": item.group, "index": item.index})
    else:  # 纯文字
        await websocket.send_json({"type": "token", "text": item})
        for sentence in splitter.feed(item):  # 文字才送给 TTS
            tts_tasks.append(asyncio.create_task(process_sentence(sentence)))
```

注意：只有纯文字才送给 TTS，标签不合成语音。存历史时也用 `strip_tags()` 处理过的干净文字。

## 10.5 前端：处理新的消息类型

在 `handleServerMessage` 里加上 `expression` 和 `motion` 两种类型的处理：

```javascript
case "expression":
    live2d.setExpression(data.name);
    break;

case "motion":
    live2d.playMotion(data.group, data.index);
    break;
```

就这两行。Live2DController 里的 `setExpression` 和 `playMotion` 在第 9 章已经写好了，现在把它们用起来。

生成完毕（收到 `done`）时，让 Live2D 回到待机动作：

```javascript
case "done":
    ...
    setTimeout(() => live2d.playMotion("Idle"), 500);
    break;
```

## 10.6 测试

重启后端，发送"你好"，观察：

- Console 里应该打印出 `表情: happy` 或类似的信息
- Live2D 的表情应该有变化（如果模型有对应的表情文件）
- Live2D 可能播放挥手动作

> **试一下**：发送一条让 AI 表现出不同情绪的消息，比如"你有什么烦恼吗"（可能触发 sad 表情），或者"哇！你真的能做到这个吗"（可能触发 surprised 表情）。看看 AI 有没有按情绪使用标签。
>
> 如果 Live2D 模型没有反应，去 Console 看看有没有报错，也可以检查模型文件夹里有没有 `expressions/` 文件夹和对应的 `.exp3.json` 文件。

到这里，你已经复刻了原项目的核心功能：

- 用户说话（语音输入）

原项目里的各个模块（`pipeline.py`、`parser.py`、`splitter.py`、`Live2DController.js`、`ActionClient.js`），你一个一个独立实现了，而且理解了每一块的原理。

---

## 本章小结

- 在系统提示词里告诉 AI 可用的标签格式
- `StreamingParser` 用缓冲区处理跨 Token 的标签，是流式解析的关键
- 解析结果分类：表情动作发给 Live2D，文字发给前端显示和 TTS
- 存历史时用 `strip_tags()` 去掉标签，保持上下文干净
