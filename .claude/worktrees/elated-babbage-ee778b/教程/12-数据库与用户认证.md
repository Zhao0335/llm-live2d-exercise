# 第 12 章：数据库与用户认证

> 上一章每个 session_id 背后是匿名的——谁都能用，也看不到谁是谁。这章实现注册和登录，让每个账号有自己的历史记录，不同用户之间隔离。

---

## 12.1 认证方案：JWT

我们用 **JWT（JSON Web Token）**做认证。它的工作原理很直接：

用户登录时，服务器验证密码，生成一个 Token（一段加密的字符串），返回给前端。前端把 Token 存起来，以后每次请求都带上它。服务器收到 Token，解密验证，就知道是哪个用户在请求。

Token 本身包含用户 ID 和过期时间，用私钥签名，没有私钥就没法伪造。服务器不需要存 Token——只要能验证签名、解出用户 ID 就够了。这叫"无状态认证"。

---

## 12.2 密码安全：绝对不存明文

**永远不要把用户密码直接存进数据库。** 数据库一旦泄露，所有用户的密码都暴露了。

正确做法是**哈希**：对密码做一个单向运算，得到一个无法还原的字符串，把这个字符串存进去。用户下次登录时，把他输入的密码做同样的哈希，和存的哈希比对，一致就验证成功。攻击者即使拿到数据库，也无法从哈希推出原始密码。

我们用 **bcrypt** 算法，它专门为密码哈希设计，故意很慢（防止暴力破解），而且每次哈希结果不同（加了随机盐）：

```python
from passlib.context import CryptContext
pwd_context = CryptContext(schemes=["bcrypt"])

# 注册：存哈希
hashed = pwd_context.hash("用户的密码")

# 登录：验证
is_ok = pwd_context.verify("用户输入的密码", hashed)
```

## 12.3 新增 User 表

在 `database.py` 里新增 `User` 模型：

- `username`：唯一，加索引（查询快）
- `email`：唯一
- `hashed_password`：存哈希，不存明文
- `is_active`：账号是否激活（方便封禁）
- 与 `ChatSession` 是一对多关系（一个用户有多个会话）

同时 `ChatSession`（原来叫 `Session`，改个名避免和 SQLAlchemy 的 Session 混淆）加一个 `user_id` 外键，允许为 `NULL`——这样未登录用户也能用，只是历史不会绑定账号。

## 12.4 auth.py：认证逻辑

新建 `backend/auth.py`，集中管理所有认证相关的函数。

**`create_access_token(user_id)`**：用 `jose` 库生成 JWT。payload 里存 `sub`（subject，用户 ID）和 `exp`（过期时间）。用 `JWT_SECRET_KEY` 签名——这个密钥要从环境变量读取，不能硬编码。

**`decode_token(token)`**：解码 JWT，提取 user_id。解码失败（Token 无效或过期）返回 `None`。

**`get_current_user`**：FastAPI 的依赖项（Depends）。从请求头 `Authorization: Bearer <token>` 里提取 Token，解码，查数据库，返回用户对象。没有 Token 就返回 `None`（允许匿名）。

**`require_user`**：另一个依赖项。调用 `get_current_user`，如果是 `None` 就抛 401 错误。需要强制登录的接口用这个。

**FastAPI Depends 的工作方式**：在路由函数的参数里写 `user: User = Depends(require_user)`，FastAPI 会自动在处理请求之前调用 `require_user`，把结果注入进来。你不需要在路由里手动调用认证逻辑，非常干净。

> **你可能会问**：JWT Token 存在 `localStorage` 里安全吗？
>
> `localStorage` 里的内容可以被同源的 JavaScript 访问，如果站点有 XSS 漏洞，Token 可能被窃取。更安全的方案是存在 `httpOnly Cookie` 里（JavaScript 无法读取）。但对于这个个人项目，`localStorage` 已经够用，不要过度工程化。

## 12.5 注册和登录接口

在 `main.py` 里加两个路由：

**`POST /api/auth/register`**：接收用户名、邮箱、密码。检查用户名是否已存在，哈希密码，创建 User 记录，生成 Token 返回。

**`POST /api/auth/login`**：接收用户名、密码。查数据库找用户，验证密码哈希，生成 Token 返回。

注意：登录失败时，无论是"用户不存在"还是"密码错误"，都返回同样的错误消息"用户名或密码错误"。这是安全实践——不要告诉攻击者账号存不存在。

**`GET /api/sessions`**：返回当前用户的所有历史会话列表，需要登录（用 `Depends(require_user)`）。

## 12.6 WebSocket 里的认证

WebSocket 不支持在建立连接时发自定义 HTTP 头，所以无法用 `Authorization: Bearer` 的方式传 Token。常见的替代方案是通过 URL 查询参数：

```javascript
const ws = new WebSocket(`${WS_BASE}/ws/chat?token=${localStorage.getItem("access_token")}`);
```

后端在 WebSocket 路由里从 `websocket.query_params.get("token")` 拿到 Token，解码得到 user_id：

```python
@app.websocket("/ws/chat")
async def websocket_chat(websocket: WebSocket):
    await websocket.accept()
    token = websocket.query_params.get("token")
    current_user = None
    if token:
        user_id = decode_token(token)
        if user_id:
            # 查数据库得到用户
            ...
```

没有 Token 也允许连接（匿名用户），只是会话不绑定账号。

## 12.7 前端：登录页

新建 `frontend/login.html`，一个简单的登录/注册表单：
- 两个 Tab 切换：登录 / 注册
- 表单提交时 `fetch` 对应接口
- 成功后把 Token 存进 `localStorage`，跳转到主页

在 `main.js` 最前面加：

```javascript
const token = localStorage.getItem("access_token");
if (!token) window.location.href = "/login.html";
```

如果没有 Token，说明未登录，直接跳转到登录页。退出登录时清空 `localStorage` 再跳转。

## 12.8 生成安全的 JWT 密钥

绝对不要用默认密钥上生产。用这个命令生成一个随机密钥：

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

把输出放到 `.env` 里：

```
JWT_SECRET_KEY=你生成的随机字符串
```

## 本章小结

- 密码用 bcrypt 哈希存储，绝不存明文
- JWT：服务端签发 Token，客户端保存，每次请求带上，无状态
- FastAPI `Depends(require_user)` 优雅注入当前用户，路由函数不需要手动验证
- WebSocket 认证用 URL 查询参数 `?token=...` 传递
- `localStorage` 存 Token，前端检查是否登录，未登录跳转登录页
